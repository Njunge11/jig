# Skill evals — report, 2026-10-05

## Verdict

The new `state-machines` rule works. A screen that names a stage now reads the name and the set of stages from the machine, and the change removes the copies that already exist.

- C10 (triggering): `state-machines` fires 3 of 3 with the new description, 1 of 3 with the old one, 0 of 3 with no plugin.
- B33 (obedience): with the new rule, 5 of 5 runs pass every point after a hand check of each judge FAIL. With the old rule, 5 of 5 runs keep a hand-written stage list. With no plugin, no run passes.

## Why the rule was added

In ajiri, the candidates page, the job page and the home page each kept their own map of stage names and their own list of stages. One stage had three names: "Longlisted", "Needs review" and, on the home page, "Rejected" for `not_a_match`. The old rule (Review item 4, "a string-keyed table carrying the stage beside the machine") never fired, because those pages read only a stored status column and never resolve a snapshot.

## The skill changes

| Skill | Change |
| --- | --- |
| `state-machines` | The description fires on a screen that names a stage or groups rows by one (tabs, a label or badge, a filter), even from a stored status column. |
| `state-machines` | Part C: the reader module reads the name (`meta`) and the set (a tag) from the machine's state nodes; a screen keeps no map, list or union of its own; URL keys go in `meta` and stay as they are; a change removes every copy that already exists. Review item 22. |
| `implementation-planner` | Step 5 check 14, and a frontend How-to-fill bullet: every stage task names the reader module, and each copy that the audit finds is a task. |

## Method

- Tool: `claude plugin eval`, Claude Code 2.1.289. Each case runs with the plugin and with no plugin.
- Model under test: Sonnet. Judge: Sonnet.
- The old-rule arm runs the same cases on jig `a672f15`, in a detached worktree.
- B33 has six graders, one per point: two regex graders (the machine's label is "Longlisted"; no literal stage name in a map, a JSX text or an array outside the machine), three LLM graders (the job page's `STAGE_LABEL` is replaced; the set of tabs comes from the machine; one reader module), and `skill-fired`.
- Each judge FAIL of a with-plugin run was checked by hand against the answer text.
- Cost that the harness reports, all runs of the day: $27.81.

### Judge FAILs that the hand check reversed

Across the last three B33 runs with the new rule, the judges gave 9 FAILs. All 9 were false; each led to a grader fix or is noted here.

- The one-reader judge failed answers that had one reader module, because the reader names the machine's tags (`"listed"`). The grader now says that a tag name is reading the machine. One more false FAIL of this kind is in the final run (with#4).
- The name judge failed answers whose names came from the reader. It is replaced by two regex graders and a narrow job-page judge.
- The name regex matched the old `STAGE_LABEL` line that an answer quoted under "Delete both constants". The regex now skips that exact line.
- The job-page judge failed an answer that replaced the constants with the reader's import beside a `// delete:` comment. The grader now counts that as the change.
