# Skill evals — report, 2026-09-19

Verdict: the skills work. The rules reach all 5 lane agents. With the plugin, Sonnet obeys the rule in 15 of 19 tasks, and 2 of the 4 misses are grader faults. With no plugin, Sonnet obeys in 5 of 19. Five cases show no gain from the plugin: in two, Sonnet already knows the rule; in three, my case is too easy to tell.

## Method

- Tool: `claude plugin eval`, Claude Code 2.1.278. Each case runs two arms: with the plugin, and with no plugin. Δ is the score difference.
- Model under test: Sonnet. Judge: Haiku (the default), 2 of 3 votes. Runs per case: 1.
- Suite: 33 cases in `plugins/jig/evals/`. The list of what each case proves is in `docs/evals/checklist.md`.
- Every rubric quotes skill text. I checked each quoted phrase and each API name against the `SKILL.md` files with `grep` before the run.
- Cost that the harness reports: $10.34 (pilot 0.15, A 1.24, B 6.10, two reruns 0.96, C 1.89).

### The two defects that started this work

- `b01`: with no plugin, Sonnet scored 0.25 on the search task. With the recipe, it narrowed in SQL, put `q` in the URL and debounced the input. This is the checklist 72 fault, and the recipe prevents it.
- `b02`: with no plugin, Sonnet did not use `useDeferredValue`; in the pilot run it used `keepPreviousData`. With the corrected step 4, it used `useDeferredValue` and the judge passed it 3 of 3. The recipe fix of `c1fc5cb` holds.

### One gap that the run showed in a skill

In `b08`, both arms sent the email inside the open database transaction. `backend-standards` has no rule on an external call inside a transaction. This is an observation. It is not a new rule; the decision to add one is open.

## Not proved

- One run per case. A score here is one sample, not a rate. Run with `--runs 3` for a rate.
- Sonnet only. Haiku and Opus were not run.
- The A cases tell the subagent to use no tool, but the harness does not keep the subagent trace. The earlier test with all file tools off proved that point for the two builders only.
- The harness judge gives no reason for a vote. `b07` and `b08` show that it can fail an answer that meets each rubric clause. Each judge FAIL in this report needs a hand check before someone acts on it; I did that check for `b07`, `b08`, `b11` and `b14` only.
- The without-arm FAIL votes were not checked by hand. If the judge is too strict there too, the true Δ is smaller than reported.
- The 5 recipes with no case: `recipe-edit-surfaces`, `recipe-expanded-panel`, `recipe-page-preview`, `recipe-rich-text`, `recipe-chat`. Also the skills `frontend-wiring`, `frontend-authoring-custom`, `implement-*`, `review-*`.
- The code samples inside the recipes are not run by these evals. An agent that copies a sample passes a rubric that quotes the sample. Only a test that runs the sample proves the sample.
